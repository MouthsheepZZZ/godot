# LRT 重建方案：HDDAGI 单向边界输入

[阅读索引](README.md) · [传播](propagation.md) · [引擎适配](engine_integration.md)

HDDAGI 仅提供 Volume 外部的低频照明条件。它不填充内部 Probe，不加入 Source，不接收 LRT 回写，也不使多个 LRT Volume 相互交换光场。

## 1. 最短链路

```text
HDDAGI 原生字段完成发布
    → LRT 适配器核对输入版本
    → 只对实际越界的六面方向采样
    → 直接读取原生已归一化的 E/π，生成宽角度近似入射 RGB
    → 发布边界输入并续充 RGB 传播预算
```

只有 `external_gi_enabled`、节点可见且原生数据可用时接入。无提供者、无覆盖或明确关闭时，越界输入为零；不改用天光、底光或其他追踪补足。

## 2. 六方向采样与单位

传播每轮使用固定的六个面邻点。设 p 是边界 Probe 中心，h 为间距，d 是从 p 指向邻点的 Volume 局部单位面方向。只有 `p+h*d` 越界时才准备对应样本：

```text
x_world = volume_to_world(p + h*d)
d_world = normalize(volume_to_world.basis * d)
L_external(p,d) = E_HDDAGI(x_world, d_world) / π
```

E 表示按法线方向积分的 irradiance。原生 diffuse 纹理的余弦卷积权重之和约为 1，已经保存 E/π；适配器直接采样，不再除以 π。适配器还原其曝光归一化并沿用原生能量和级联采样含义。输出为未曝光的线性 HDR RGB，不乘接收材质 albedo 或 LRT 的 G。

E/π 是宽角度平均入射 radiance 的固定近似：常量环境下单位一致，但不恢复真实方向分布。删除 26 方向投影、SH 逆余弦核及亮度拟合，不把原生 irradiance 直接称为精确方向 radiance。

边、角上的每个越界面方向各自在自己的外部邻点采样，不能统一把采样位置偏到角外。核心不解析 HDDAGI 的级联、occlusion、纹理或曝光信息。

只保存有越界连接的边界样本及必要覆盖状态，不分配内部 Probe 的完整外部 RGB SH 场。数据寻址由适配器提供，核心只按边界连接读取 RGB；不要求逐 Probe 变长记录。

## 3. 接入传播，不接入 Source

内部邻点仍使用 `dot(R_previous(q), Y(d))`。越界邻点改用上面的标量 RGB，进入同一个 Gather：

```text
L_c(j) = 邻点在 Volume 内 ? dot(R_previous_c(qj), Y(dj))
                          : L_external_c(p,dj)
Incoming_c = (4π/6) × Σ(六面通畅 j) P(dj) × L_c(j)
```

之后仍执行固定局部反射、k 和 Source 相加，不增设外部 GI 专用反射 pass。

覆盖状态必须区分有效黑色与无覆盖。覆盖丢失、提供者移除和开关关闭时清除旧有效输入并续充传播预算，不能继续使用旧边界。有限轮后仍可能存在历史 Radiance，按传播预算处理，不倒扣历史。

## 4. 天空归属：明确接受重复近似

HDDAGI 的原生 diffuse 场可能同时包含表面反弹和射线未命中时读到的直接天空，不能将其统称为“只有天空反弹”。

本方案接受完整混合字段作为边界输入，不要求 HDDAGI 按来源拆分，也不因其读取天空而拒绝接入。LRT 自身仍计算本地 SkyBounce，并在接收面单独处理直接环境漫反射；因此可能重复部分天空贡献，形成偏亮。这是已接受的近似。

- LRT 不再额外向边界添加一份天空。
- 不使用 `includes_sky`／`exclude_sky` 将整个混合场拒绝。
- `receive_sky=false` 仅关闭 LRT 本地天空链，不能从外部混合输入或已有 Radiance 中挑出天空删除。
- 要完全不接收外部混合天空，可关闭 `external_gi_enabled`；这会同时关闭全部外部边界输入。

Basepass 不再把原生 HDDAGI 全量叠到已被 LRT 覆盖的区域。边缘的原生输入按 Coverage 过渡，见 [Gather](screen_gather.md)。这一合成规则不等于能消除边界字段内部的天空重复。

## 5. 发布版本驱动

不每帧无条件重采，也不通过 GPU 内容读回判断变化。适配器比较当前完整发布状态和上次采样所用状态：

- 原生已发布光场内容及资源身份。
- 覆盖、级联布局／位置和采样相关参数。
- 能量及曝光归一化。
- Volume 变换、网格和边界开关。
- 原生采样确实依赖的相机参考位置。

原生版本必须反映实际发布内容，不以“经过了一帧”冒充内容变化。若现有版本不足，只在必要发布点补充版本交接，不为了停更修改 HDDAGI 的积分算法。

有效状态不变则复用边界。发生变化后合并为最新一次请求，在对应原生写入完成后采样，按一致版本发布并续充 RGB 预算；不重放每个旧请求。GPU 屏障和字段生命周期由适配器负责。

HDDAGI 若持续发布变化结果，即使场景静止，也可能使 LRT 持续活跃。本方案不承诺此时停更，不加固定低频设置、阈值读回或隐藏节流来掩盖成本。

## 6. 实施验收

核对恒定环境下 E/π 的单位、Volume 旋转与方向、六面和边角的真实采样位置、级联过渡、覆盖丢失、有效黑、曝光变化、节点隐藏恢复，以及无变化版本不重采。

还需观察混合天空偏亮、E/π 方向损失和持续 HDDAGI 更新的完整成本。现有局部算子的 CPU 模型没有验证这些接口和画面。

# LRT 重建方案

目标：用简单、低成本的链路获得大尺度 GI 氛围，接受低频、颜色平均及有限迭代误差。本文档集是已确认的重构设计；当前实施与验证状态见下节。

## 当前实施与验证（2026-10-19）

- 主链已接入：粗几何与增量局部记录、合并 Source、固定六面有限传播、独立天空位递推、双输出低分辨率 Gather。
- HDDAGI 改为原生只读字段描述和发布版本，由 LRT 自己采样六面外部邻点的 `E/π`；仅保存越界连接的 RGB 与覆盖状态。删除旧 Provider、26 向反卷积和额外 Volume 阴影绘制。
- 接口已收敛为 4 项 Project Settings、7 项节点设置、8 个全局 Debug View；删除旧脚本属性别名、暂停、单步、reset 入口及独立材质／Transfer 调试视图。Probe 间距默认 0.5 m。
- 重构主链阶段的默认配置及 `lrt_hddagi=no` 完整 Windows editor 构建通过，两种配置各通过 85 项 LRT 测试；固定六面修复后的默认配置重新构建并通过 85 项 LRT 测试。`module_lrt_enabled=no` 下，GI、Forward+、场景 shader 与场景剔除的受影响编译单元通过；未链接完整禁用模块的编辑器。
- 实际 D3D12 GPU 检查通过：恒定 irradiance 的 `E/π`、旋转／平移、六面与边角连接寻址、退化单轴网格、有效黑、无覆盖，以及能量／曝光归一化；最大绝对误差约 `1.37e-7`。
- carriage 场景验证了隐藏后停止几何检查与边界采样、恢复重新接入、关闭外部 GI、提供者移除后清零，以及无变化输入耗尽预算后停止 RGB 传播。已检查普通照明、粗几何、边界及天空调试画面；退出粗几何调试后，其 GPU 缓冲统计归零。multi_volume 场景中的两个 Volume 均无构建错误，并各自耗尽预算停更；该检查不代替优先级／覆盖的完整画面对照。
- 单场景 GPU 观测：RTX 5080、1440×900、半宽半高 Gather，24 次读数的边界采样均值约 0.0098 ms、Gather 约 0.0268 ms；不包含其余 LRT 阶段。该 Volume 的 2776 个边界连接占 44,416 字节。

仍需进行薄墙／多 Volume／级联过渡的系统画面对照、完整成本测量及实际分配失败注入。外部测试工程的主入口、运行时控件与旧调试枚举已适配，四个场景切换、8 个调试视图及 4 项定向回归通过；有限预算回归已改为在真实游戏帧中验证自动停更、每帧限额、max 续充、emission 唤醒及隐藏／恢复，52 个断言通过；共用灯光夹具已适配当前属性，方向光 Source 定向回归的 19 个断言通过。其余旧回归中依赖手动传播控制、属性别名或旧资源布局的逻辑仍需逐项迁移，不通过恢复旧接口兼容。

## 车厢画面缺陷：阴影 bias 与三相传播已修复

方向光阴影 bias 空间错误及四点轮换的三相振荡均已修复。固定六面算子已完成 CPU/GPU 数值对照、持续传播及相机运动验证；薄墙、多 Volume、天空与原生覆盖过渡的整体验收仍按前述范围继续。

### 已修复：方向光阴影 bias 空间错误导致错误 Source

`modules/lrt/lrt_volume.cpp` 上传的方向光 bias 与原生一致，是投影前的位置偏移量；修复前 `modules/lrt/lrt_inject.glsl` 把它直接加在投影后的归一化深度上。原生 `scene_forward_clustered.glsl:2352` 则先执行 `position += light_dir * shadow_bias` 再投影。旧 LRT 的偏移尺度因此依赖阴影投影范围，过度放宽深度比较，给被遮挡 Probe 注入无阴影直射反弹。

- 隔离条件：`external_gi_enabled=false`、`receive_sky=false`，相机固定在 `(0,3.2,13)`，保持作者灯光能量及曝光。删除并重建游戏实例中的 Volume，使两次比较都从冷场开始，避免历史残留；两次均执行 65 轮。
- 方向光 `shadow_bias=0.1` 时，红色 Source DC 全场和为 `782.15727`；仅临时将 bias 设零后为 `287.11245`。三个固定空间点 `(-1.5,3.3,8)`、`(-1.3,4.3,8)`、`(0,4.5,8)`，沿 `+X` 核重建的红色 GI 分别由 `0.35180 / 0.36952 / 0.40558` 降至 `0.05980 / 0.02307 / 0.02194`。这些是指定位置、指定法线的数值样本，不都对应可见墙面。
- Probe `2145/3537/4934` 到太阳方向的 CPU 原始三角形射线均命中车体，默认 bias 下 Source DC 为 `0.74885 / 0.71266 / 0.73102`，bias 为零时三者均归零。改变相机位置或反转阴影剔除面不能消除该样本错误。
- 冷场中将方向光 `light_indirect_energy` 临时置零时，红色 Source 与 Radiance 都严格为零；排除了该红色信号由隐藏底光或 Gather 凭空生成的可能。

修复已在方向光当前级联及混合的下一级联中，分别沿 Volume 局部光方向施加位置 bias 后再投影；方向光不再向投影后深度追加同一偏移。保留作者 bias、级联选择、覆盖及淡出逻辑，未修改点光／聚光路径。

Windows editor 完整增量编译与链接通过，新编辑器已启动。车厢保持作者 `bias=0.1`，关闭本地天空及外部 GI 作隔离检查时，上述三个 Probe 的 Source 全为零，全场红色 Source DC 和为 `287.11245`，与诊断时零 bias 的结果一致。恢复场景默认天空及外部 GI 后已检查完整光照画面，室内整体泛白明显减轻，无运行错误。

`G:/lrt_godot_test/tests/test_lrt_lights.gd::run_directional_shadow_bias_regression()` 在真实游戏帧中覆盖单级／两级／四级阴影及 `30 m / 300 m` 阴影距离，保留 `bias=0.1` 和级联混合设置：六种配置无遮挡时 Source DC 合计均约 `2.71402`，添加遮挡后均为零；随后扩展相机后方 Probe 的实际遮挡及无遮挡对照，共 55 个断言通过。

### 已修复：四点分相传播产生持续周期输出

关闭外部 GI 后，小幅移动相机（X 方向振幅 0.03 m）仍会更新 Source 版本并重新启动传播。`refresh_native_source_for_view()` 比较原生级联矩阵和相机深度等完整输入，因此版本变化本身不证明源项数值变化。修复前的 `lrt_propagate.glsl` 按迭代切换三个四点算子，直接发布每相结果，没有共同固定点或完整方向估计的保证。

- 默认 bias 下，固定相机和 Source，401 轮预算推进 300 帧后，指定空间样本 `(-1.5,3.3,8)`、`+X` 核的红色 GI 在 `0.35289094 / 0.32948673 / 0.35637641` 间循环，三个周期重复。
- 即使临时把 bias 设零以隔离上面的注入错误，真实屏幕表面位置 `(-1.68117,2.35768,6.86541)`、近似 `+X` 法线处，迭代 `365–373` 的红色 GI 仍为 `0.03489928 / 0.03208430 / 0.03780252`，三个周期完全重复，峰峰值约为均值的 `16.37%`。此时红色 Source 逐系数完全相同，且本地天空和外部 GI 都关闭。

该振荡发生在屏幕 Gather 之前，与阴影 bias 错误独立。修复改为每轮固定读取六面、积分权重 `4π/6`，以相同六面单位响应重新校准单个 k；删除分相 hash、逐相权重及相位统计。保持每帧一轮、有限预算和原始 SH4 A/B，不增加显示平滑、三相历史或钳制。局部缓存格式升至 17、内容身份版本升至 26，旧三相 k 不会继续加载；局部记录仍为 128 字节，对齐余量写零。

修复后的证据：

- Windows editor（`tests=yes`）构建、链接成功；`--headless --test --test-case='*LRT*'` 的 85 项、452702 个断言全部通过，覆盖六面布局、全部 64 种面通行组合与随机局部输入的单位／有符号能量界、缓存及 shader 编译。
- 真实 GPU 正／负光源对照：独立 CPU 六面递推检查完整 RGB SH4，分别通过 78／79 个断言，最大绝对误差约 `9.54e-7`。自动有限预算的 52 个断言继续通过。
- 新增 `run_stability_regressions()`：旋转、平移的独立 World 内，256 帧预热后保持每帧一轮，移动相机并观察 32 帧，完整 RGB 系数最大帧差 `2.38e-7`；Source 不变，实际执行 32 轮，36 个断言通过。
- 车厢同一真实表面点在固定 Source 下，连续 12 轮约为 `0.04862657`，最大差约 `1.12e-8`，不再出现三相周期。
- 车厢相机横向 ±0.03 m 并改变朝向，各观察 32 帧：关闭本地天空／外部 GI 时，该点红色 GI 相对跨度约 `1.23e-6`；启用两者时约 `2.62e-7`，Source 均逐系数不变。实际 GI 输出三位置截图已检查；对应表面像素红色／蓝色相同，绿色仅有 1/255 的屏幕取样差异。
- 更大运动：横向 ±0.3 m、纵向 ±0.5 m，默认天空及外部 GI 开启，72 帧中该点 GI 为 `0.05633879–0.05687219`，最大帧差约 `1.95e-5`，没有原先的三相跳变。
- RTX 5080、车厢 6496 个 Probe、每帧一轮，24 个读数的传播 GPU 均值约 `0.01739 ms`；是新算子的观测值，不是与旧算子同条件的性能对比。

### 已修复：保守体素化的几何／材质覆盖不一致

原先普通 Mesh 的 CPU 保守几何网格与原生材质捕获网格分开生成。几何有覆盖但单点材质查询未捕获时，零值被当成黑色反射率参与平均；纯白材质也会出现黑块。

普通 Mesh 现统一使用原生材质 pass 的保守覆盖，同时写入几何法线、albedo 与 emission。硬件保守栅格化覆盖投影像素，主轴 fragment 再覆盖像素足迹的完整深度区间；几何与材质为 1:1 网格，反射率只存一份 RGB565，不跨表面补色。撤回纯色 Mesh 常量捕获特判，既有解析 Box 路径保留。世界坐标捕获的变换进入运行时几何签名和持久缓存键；内容身份版本升至 29。

- 默认 Windows editor（`tests=yes`）完整构建、链接通过；87 项 LRT 测试、452856 个断言通过，包括相邻白色／黑色发光 voxel 的 1:1 解码及整组移动／旋转的缓存失效。
- RTX 5080、D3D12 的 10 项实际 GPU 定向检查通过：纯白、白色贴图、彩色贴图、真实黑色、Shader 顶点变形、fragment 裁剪、亚像素三角形、其顶点位移、前表面遮挡后方发光，以及整组旋转自动重建。白色输入均无误黑；彩色贴图最大通道误差约 0.02008，包含 RGB565／RGB8 量化；真实黑色的 930 个表面样本仍为黑色。裁剪将占据 Probe 从 540 降至 320，旋转后应用代次从 1 升至 2。
- 后方发光隔离：前侧 Probe 的红色 EmissionSH DC 为 0，后侧为约 7.125；未通过跨格混色消除空洞。GPU 报告保存在 `%TEMP%/lrt-unified-capture-report.json`。
- carriage 保持原材质时，26381 个表面 Probe 中 RGB 全近零值为 0；将 70 个网格临时全部换成白色贴图后，34197 个表面 Probe 的非白值与黑值均为 0。已检查原问题位置的粗几何和实际 GI 画面；截图为 `%TEMP%/lrt-unified-authored-geo.png`、`lrt-unified-authored-gi.png` 和 `lrt-unified-white-texture-geo.png`。

D3D12 已实机验证；Vulkan 扩展路径已编译，尚未实机验证。保守捕获要求对应硬件能力，设备不支持时明确报错；不增加 Probe 有效性权重或 Gather 采样次数。相较此前的纯色 Mesh 常量捷径，构建阶段增加 GPU 捕获和回读；完整性能对比尚未测量。

### Gather 的局部数值对照与验证缺口

在上述 bias 为零的诊断实例中，对六个屏幕位置采样实际深度、法线、RGB 场及 Lighting 输出，用 CPU 八点插值和生产核重建红色 GI，最大绝对误差约 `5.35e-6`，Coverage 最大误差约 `2.29e-5`，符合半精度输出量化。该检查未发现这些样本的寻址／核错误，不代替跨轮廓、多 Volume 和运动验收。

旧 `test_lrt_receiving.gd::_read_direct_gather` 对原生深度／法线直接 `texture_get_data`，会因缺少 `TEXTURE_USAGE_CAN_COPY_FROM_BIT` 返回空数组，不能据此宣布 Gather 通过或失败。本次有效对照改用临时计算 shader 按生产采样权限将六点深度／法线写入可读回的存储缓冲，未修改引擎纹理标志。

上述排查只改变游戏实例，未修改作者场景；临时参数均已恢复。随后按用户要求依次修复方向光 bias、固定六面传播和相机后方 Probe 的原生阴影采样。后续继续验证粗几何／LTM、天空、薄墙、多 Volume 及原生覆盖过渡，不能把这些缺陷的修复当作全部 GI 验收完成。

## 共同约束

- 主要实现集中在 `modules/lrt`，原生接口通过 LRT 专属 C++／shader 适配器交接。
- 不保留旧算法兼容路径，不重构无关 Godot 代码；最小改动指最小长期耦合面，不是本次 diff 行数最少。
- 无 CPU 缓存预算、Volume 显存上限或自动降分辨率；真实分配失败需报告并退出失效 Volume 的合成。
- 隐藏 Volume 停止其计算和显示，保留资源；恢复时校验最新输入。
- HDDAGI 仅向越界方向提供外部输入。接受其混合天空造成的偏亮，不要求修改 HDDAGI 求解器来拆分来源。
- Debug View 仍使用现有 Display Advanced → LRT 全局菜单，严格 8 项；无暂停、单步或独立诊断面板。

设计阶段的 CPU 数学模型只覆盖局部算子与天空位递推；后续引擎与 GPU 验证范围见“当前实施与验证”。
